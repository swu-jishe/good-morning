# Goal Radar（目标雷达）前端 Demo Spec

## 1. 文档定位

本文档用于定义比赛 Demo 的**前端设计方案与演示叙事**，用于指导假前端搭建与 5 分钟展示视频内容组织。

- 范围仅限：产品定位、页面结构、信息层级、交互形态、视觉语言、演示重点
- 明确不包含：技术架构、程序实现、后端设计、真实数据接入方案

## 2. 产品定义

### 2.1 产品名称

**Goal Radar / 目标雷达**

### 2.2 产品一句话定义

一个面向大学生的学业与升学信息聚合工作台，将分散的信息源统一收拢、转化为可执行日程，并通过 Agent 提供整理、规划与辅助决策。

### 2.3 Demo 核心价值

本 Demo 需要在短时间内让评委清晰感知三件事：

1. **信息聚合能力**：把竞赛、考研、课程、考试、学校通知等异构信息统一呈现在同一工作台中
2. **AI 助理能力**：不是泛聊天，而是围绕“整理信息—形成行动—辅助推进”提供 Agent 化支持
3. **整体产品感**：界面结构清晰、视觉统一、交互完整，呈现出可落地的产品形态

## 3. 目标用户与场景

### 3.1 核心用户画像

默认用户为**大三计算机专业学生**，当前主目标为**考研升学**。

### 3.2 扩展适配方向

同一套前端结构应可自然扩展到以下目标模式：

- 竞赛冲刺
- 保研准备
- 求职投递

### 3.3 使用场景

用户每天面对的信息来源分散、时间节点密集、优先级冲突明显，需要一个统一入口完成：

- 查看今日重点与近期风险
- 理解不同来源的新通知与截止信息
- 将信息转化为待办或日程安排
- 通过 Agent 快速获得归纳、排程与建议

## 4. 信息来源范围

Demo 中展示的信息来源包括但不限于：

- **竞赛信息**：计算机设计大赛、ACM 等
- **考研信息**：报名时间、初试节点、院校动态、资料提醒
- **课程作业**：学习通作业、实验报告截止时间
- **期末考试**：教务系统中的考试与教学安排
- **学校活动通知**：钉钉或校内平台中的讲座、活动、宣讲信息

说明：这些来源在 Demo 中作为前端信息类别使用，用于展示“聚合后的产品形态”，不展开真实接入方式。

## 5. 产品叙事主线

本 Demo 的主叙事应保持为：

**多源信息进入工作台 → 系统完成聚合与优先级组织 → 用户看到重点事项与风险 → Agent 协助解释、排程和推进执行。**

因此，产品核心不是“聊天”，而是“围绕目标推进的信息工作台”。

## 6. 信息架构

正式结构定义为：**3 个主页面 + 右侧常驻 Agent 抽屉**。

### 6.1 页面一：聚合工作台

这是 Demo 的主视觉页面，也是主要展示页面。

#### 页面目标

- 让用户一眼看到当前目标状态、近期重点和多源信息聚合结果
- 强化“工作台”而非“消息列表”或“聊天工具”的产品认知

#### 页面结构

- **左侧区域**：导航与筛选区
- **中间区域**：Bento 聚合工作台
- **右侧区域**：常驻 Agent 抽屉（跨页共用）

#### 左侧区域内容

- 页面导航入口
- 当前目标模式标签（如考研模式）
- 信息来源筛选
- 优先级筛选
- 时间范围筛选

左侧区域应保持窄而稳定，承担定位与筛选作用，不抢主视觉。

#### 中间区域定位

中间区域采用 **Bento Grid（便当盒）式模块化布局**，通过不同尺寸卡片表达信息重要性。

#### 首页卡片层级

首页大卡位置以 **AI 简报 + 高优预警** 为最强势内容，这是比赛叙事中的优先展示重点。

- **大卡（最高权重）**
  - AI 每日简报：总结最新变化、今日重点、建议动作
  - 高优预警：展示迫近的截止日、关键通知、冲突提醒
- **中卡（次高权重）**
  - 考研倒计时
  - 今日重点清单
  - 时间轴 / 今日进程
- **小卡（补充入口）**
  - 单条通知摘要
  - 竞赛入口
  - 课程作业入口
  - 学校活动入口
  - AI 建议摘要

#### 首页核心模块建议

1. **AI 每日简报卡**：放在视觉中心或左上核心位，承担“聚合解释器”的作用
2. **高优预警卡**：紧邻 AI 简报，直接体现风险与行动压力
3. **考研倒计时卡**：保持目标感与长期叙事
4. **今日重点卡**：突出当天最值得处理的事项
5. **时间轴卡**：作为过程类信息，不抢主叙事，但必须存在
6. **来源资讯卡组**：按竞赛、课程、通知等主题切分为小模块

#### 首页关键交互

- 点击任一卡片，可进入日程详情页或展开具体信息
- Hover / Focus 状态通过轻微抬升、阴影增强、边框高亮体现可操作性
- 首页不强调复杂操作，更强调“快速扫描—快速进入下一步”

#### 首页 Demo 镜头重点

- 打开页面后先看到 AI 简报与高优预警，迅速建立产品价值
- 展示多来源卡片在同一工作台中共存，体现聚合能力
- 从某条重点事项点击进入详情，再由 Agent 辅助解释或排程，形成连贯叙事

### 6.2 页面二：日程详情页

这是待办 / 日历 / 单条事件详情整合后的总览页。

#### 页面目标

- 承接首页中的重点事项
- 让用户查看具体时间、来源、摘要、优先级和动作建议
- 把“信息”转化为“行动视图”

#### 页面结构

- **左侧主区域**：日历视图 / 清单视图切换
- **右侧详情区域**：事件详情、来源说明、关联动作
- **最右侧**：常驻 Agent 抽屉

#### 页面核心内容

- 月历或周历总览
- 今日 / 本周待办列表
- 单条事件详情面板
- 事件来源标签
- 优先级标识
- 可执行动作入口（如标记完成、加入计划、询问 Agent）

#### 单条事件详情应展示的信息

- 标题
- 时间
- 来源
- 摘要
- 优先级
- 建议动作

#### 页面交互重点

- 支持月历与清单视角切换
- 点击某条事件时，右侧详情即时更新
- 用户可从详情直接唤起 Agent 进行排程、解释冲突或生成建议

#### 页面 Demo 镜头重点

- 从首页点击一个高优事项进入本页
- 展示该事件的来源、时间与处理建议
- 由 Agent 给出“如何安排本周”或“是否延后某项任务”的响应

### 6.3 页面三：订阅配置页

这是信息聚合的控制枢纽页面。

#### 页面目标

- 解释“为什么工作台能看到这些信息”
- 展示用户可主动定义自己的关注范围与提醒方式
- 体现产品的可配置性与成长性

#### 页面结构

- 顶部：分组标签（信息源 / 关注词 / 提醒级别 / 目标模式）
- 中部：配置卡片流
- 右侧：常驻 Agent 抽屉

#### 页面核心内容

- 信息源开关
- 关注关键词配置
- 提醒强度或提醒级别
- 目标模式切换（考研 / 竞赛 / 保研 / 求职）

#### 页面交互重点

- 打开或关闭某类来源时，用户应感知到工作台内容会随之变化
- 调整目标模式时，界面文案与建议重点可以发生前端层面的上下文变化
- Agent 可在此页承担“配置顾问”角色，帮助用户优化订阅范围

#### 页面 Demo 镜头重点

- 展示用户开启一个新的信息源或切换目标模式
- 再返回工作台，形成“配置变化—工作台变化—Agent 给出新建议”的闭环

## 7. 右侧常驻 Agent 抽屉

### 7.1 定位

Agent 抽屉是跨页面常驻的辅助中枢，不是独立主页面，而是整个产品中的“行动转化层”。

### 7.2 形态定义

- 默认位于右侧，可收起、展开、拉伸
- 收起时保持明确可见的入口，不应完全消失
- 展开时与当前页面并存，而不是完全替代页面内容

### 7.3 跨页上下文原则

同一个抽屉在不同页面中，必须通过以下方式体现上下文变化：

- 默认选中的 Agent 不同
- 输入框预设问题不同
- 顶部上下文标签不同

示例：

- 在聚合工作台：偏向“总结、提醒、判断优先级”
- 在日程详情页：偏向“排程、冲突处理、拆解任务”
- 在订阅配置页：偏向“新增来源、优化关注范围、调整提醒策略”

### 7.4 Agent 正式命名

考虑比赛展示与 spec 表达的一致性，采用更正式专业的命名：

1. **信息研判 Agent**
2. **日程规划 Agent**
3. **策略支持 Agent**

### 7.5 Agent 职责定义

#### 信息研判 Agent

- 聚合并概括多来源信息
- 提炼重点变化
- 帮助用户快速判断哪些信息值得处理

适合出现于：聚合工作台、订阅配置页。

#### 日程规划 Agent

- 围绕任务、日程、冲突和优先级提供建议
- 将重点事项转化为可执行安排
- 帮助用户理解“今天做什么、这周怎么排”

适合出现于：日程详情页、聚合工作台。

#### 策略支持 Agent

- 提供面向目标推进的补充建议
- 在考研 / 竞赛 / 保研 / 求职等模式中给出不同策略视角
- 承担解释、建议、激励与方向支持功能

适合全局出现，作为补充型 Agent。

### 7.6 默认入口文案建议

- **信息研判 Agent**：为你整理了今日最值得关注的变化，要先看重点还是先看来源？
- **日程规划 Agent**：你今天还有 2 项高优先级事项，需要我帮你重新安排吗？
- **策略支持 Agent**：基于你当前的目标模式，我可以帮你判断下一步该优先投入什么。

## 8. 视觉设计语言

整体视觉语言统一采用 **Material Design 3 Expressive**。

### 8.1 总体气质

- 现代、清晰、友好
- 有明显层级，但不过度复杂
- 强调圆角、容器感、节奏感与重点信息突出

### 8.2 组件气质要求

- 卡片需具有明确容器边界
- 交互元素需具备清晰 Focus / Hover / Active 状态
- 模块之间通过层级与节奏区分，而不是依赖大量分割线

### 8.3 来源颜色表达规则

不同来源通过**局部色彩语义**表达，不采用整页大面积分色。

推荐使用方式：

- 标签色条
- 边框高亮
- 状态点
- 局部底色或来源徽标

这样既能表达来源差异，又不会破坏整个工作台的统一感。

### 8.4 视觉统一规则

- 全站保持统一圆角体系
- 卡片阴影和层级规则统一
- 页面标题、分组标题、正文说明保持稳定的层级关系
- 右侧 Agent 抽屉在所有页面中的视觉骨架保持一致，只改变内容上下文

### 8.5 动效原则

- 动效服务于信息层级变化与状态反馈，不做纯装饰
- 页面切换、卡片展开、抽屉开合应体现柔和弹性与连续感
- 动效应突出“信息被收拢、被唤起、被处理”的过程感

## 9. 演示视频建议节奏

### 9.1 开场

先展示聚合工作台，快速建立“一个页面汇总多源信息”的第一印象。

### 9.2 第二段

突出 AI 简报与高优预警，说明系统不只是展示信息，而是已经帮助用户完成初步整理。

### 9.3 第三段

从首页点入日程详情页，展示一条事项的时间、来源、摘要、优先级与动作建议，再由 Agent 辅助排程。

### 9.4 第四段

进入订阅配置页，展示信息源开关或目标模式切换，说明产品具备自定义能力。

### 9.5 收束

回到工作台，展示配置变化后的聚合结果或新的 Agent 建议，形成完整闭环。

## 10. 本次 Demo 的设计结论

本 Demo 以前端工作台为核心，采用 **“3 个主页面 + 右侧常驻 Agent 抽屉”** 的结构，用 **Bento 聚合工作台** 承载信息聚合，用 **日程详情页** 承载行动化解释，用 **订阅配置页** 承载信息控制，并通过 **信息研判 Agent、日程规划 Agent、策略支持 Agent** 三个明确角色把信息进一步转化为建议与动作。

最终呈现目标是：让评委在短时间内明确感受到，这不是一个普通聊天界面，而是一个围绕大学生目标推进而设计的、具有完整产品感的智能信息聚合工作台。
