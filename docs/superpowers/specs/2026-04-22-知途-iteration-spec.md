# 知途（ZhiTu）迭代落地 Spec

## 1. 文档定位

本文档用于对齐《作品报告》第三章与当前 project demo 的实际开发进度，输出一份新的迭代落地 spec。

本文档关注以下三类内容：

- 产品结构如何从现有 demo 演进到更完整的“知途”形态
- 前端页面、模块、状态与交互如何承接第三章中的关键能力
- 哪些能力在本轮以“前端可见闭环”方式落地，哪些暂不进入实现范围

本文档**不涉及**后端架构、真实自动执行链路、隐私安全机制细节与底层模型实现。

---

## 2. 当前项目现状与迭代目标

### 2.1 当前 demo 已有基础

当前 project 已具备以下可复用骨架：

- 以 `App.tsx` 为核心的多页面切换结构
- 聚合工作台、日程详情、订阅配置三类主视图
- 右侧常驻 Agent 抽屉
- AI 简报、高优预警、时间轴、多源信息卡等首页内容
- 日程清单 / 月历切换与事件详情展示
- 信息源接入池、关注词、原始抓取池等配置雏形
- 3 个 Agent 的前端角色切换与预设交互

### 2.2 当前 demo 与《作品报告》第三章的差距

当前 demo 仍缺少以下关键表达：

- “个人成长档案区”的独立产品化呈现
- Skill 的能力边界、输入输出与规则约束的前端表达
- 多智能体任务理解、拆解、协同决策的显式界面
- 基于平台联动的“建议 → 确认 → 回写 → 反馈”闭环
- Agent 对话与主页面任务卡片的双向联动

### 2.3 本轮迭代目标

本轮迭代的目标不是重做一套新系统，而是在当前 demo 骨架基础上，将《作品报告》第三章中最关键、最需要“落地感”的部分转译为可被评委看懂、可被前端承接、可被后续开发继续推进的产品结构与交互规则。

## 3. 产品定义重构

### 3.1 产品名称

产品统一命名为：**知途（ZhiTu）**。

### 3.2 产品定位

知途不是一个单纯展示信息的工作台，也不是泛化聊天机器人，而是一个面向大学生学业与升学场景的 **任务理解与行动闭环工作台**。

它的核心价值不是“告诉用户发生了什么”，而是把多源信息转化为：

- 当前应关注什么
- 为什么重要
- 应该采取什么行动
- 是否需要写入日程 / 提醒 / 执行队列
- 当前行动是否已经回写并产生结果

### 3.3 核心叙事主线

知途的产品主线统一表述为：

> 多源信息进入系统 → 系统完成重点识别与风险判断 → 多 Agent 形成任务理解与行动建议 → 用户在对话中确认或改写 → 系统将结果回写到日程、提醒或执行队列 → 用户在后续页面中看到结果反馈。

该主线直接对应《作品报告》第三章中的界面设计、多智能体协同与平台联动机制。

---

## 4. 信息架构

### 4.1 总体结构

新一轮迭代后的知途采用：

**4 个主页面 + 右侧常驻 Agent 抽屉**

包括：

1. 聚合工作台
2. 日程详情页
3. 订阅配置页
4. 成长档案页
5. 右侧常驻 Agent 抽屉（跨页面存在）

### 4.2 与《作品报告》第三章四大区域的映射

- **智能对话区** → 右侧常驻 Agent 抽屉
- **信息展示区** → 聚合工作台 + 日程详情页的信息区
- **任务提醒区** → 聚合工作台中的高优预警区域 + 日程详情页中的执行区
- **个人成长档案区** → 新增的成长档案页

### 4.3 信息架构调整原则

本轮不是推翻现有三页结构，而是在现有基础上：

- 保留聚合工作台、日程详情页、订阅配置页
- 新增成长档案页作为长期上下文承载页
- 强化右侧 Agent 抽屉的跨页面任务编排能力

## 5. 页面级落地设计

### 5.1 聚合工作台

#### 页面定位

聚合工作台是知途的全局入口页，承担“信息展示区”的主体角色，并承接一部分任务提醒与任务理解入口。

#### 当前可复用内容

- AI 简报
- 高优预警
- 今日目标
- 时间轴
- 多源信息卡

#### 本轮新增模块

- **任务理解卡**：把一条复杂通知或事件转换为“当前需要做什么”的结构化结论
- **协同决策卡**：显示三个 Agent 分别给出的判断摘要，并形成汇总行动建议
- **一键进入编排**：从卡片直接进入 Agent 对话编排流程
- **档案摘要卡**：展示当前长期目标、阶段重点与成长主线，作为成长档案页的首页入口

#### 页面职责

本页不直接承担所有执行细节，而是完成三件事：

1. 让用户快速看到当前最重要的信息与风险
2. 让用户把信息转入任务理解 / 任务编排流程
3. 让用户感知当前目标与长期主线并进入下一步操作

### 5.2 日程详情页

#### 页面定位

日程详情页是知途的执行与反馈主页面，承担“任务提醒区”的核心角色。

#### 当前可复用内容

- 清单视图
- 月历视图
- 单条事件详情

#### 本轮新增模块

- **任务拆解区**：展示主任务、子任务、建议时间与优先级
- **执行确认区**：用于确认是否写入提醒、加入日程或进入执行队列
- **结果反馈区**：展示动作是否生效，以及当前状态
- **编排回写提示**：标记某个任务是否由 Agent 创建、修改或重新排期

#### 页面职责

本页重点承接“已理解任务”的后续处理，让用户看到：

- 任务是否已被拆分
- 任务是否已被排程
- 用户是否确认了执行动作
- 最终结果是否成功回写

### 5.3 订阅配置页

#### 页面定位

订阅配置页是知途的规则管理与输入源管理页面。

#### 当前可复用内容

- 信息源接入池
- 原始抓取池
- 关注词

#### 本轮新增模块

- **Skill 规则区**：展示不同类型任务由谁处理、可以生成什么结果、哪些动作需要确认
- **提醒策略区**：展示高优预警条件、默认回写方式与提醒强度
- **异常回执区**：前端化表达“待确认 / 无法自动执行 / 仅建议不回写”等状态

#### 页面职责

本页负责把《作品报告》第三章中偏系统性的能力规则转译成用户可理解的配置项与状态说明，使 Skill 能力不只停留在概念层，而能在前端中形成“规则面板”的观感。

### 5.4 成长档案页

#### 页面定位

成长档案页是本轮新增主页面，用于承接《作品报告》第三章中的“个人成长档案区”。

#### 页面核心模块

- **长期目标卡**：如考研、竞赛、保研、求职等主线目标
- **阶段进展卡**：当前阶段任务完成度与重点节奏
- **能力画像卡**：课程、考试、竞赛、技能积累的阶段性轮廓
- **关键里程碑**：重要节点与已完成记录
- **上下文摘要**：当前 Agent 已加载的长期背景标签

#### 页面职责

本页不是普通“个人资料页”，而是把长期记忆、阶段目标与成长主线做成前端可见页面，让 Agent 后续给出的建议看起来真正建立在长期上下文之上。

## 6. Agent 抽屉与智能对话区

### 6.1 定位

右侧常驻 Agent 抽屉是知途的智能对话区，也是多智能体任务理解与任务编排的统一承接容器。

### 6.2 角色分工

本轮保持现有 3 个 Agent 的角色分工，但其表达方式从“各自对话”升级为“协同决策”：

- **信息研判 Agent**：负责识别事件性质、重要度、风险点与来源价值
- **日程规划 Agent**：负责任务拆解、时间安排、提醒建议与排期
- **策略支持 Agent**：负责结合长期目标提供优先级、取舍与阶段建议

### 6.3 新的抽屉职责

抽屉不再只承担聊天功能，而需要承担以下四项职责：

1. 展示当前页面上下文
2. 承接引用进入的任务卡 / 信息卡
3. 输出任务理解与协同决策结果
4. 提供任务修改、编排与确认回写能力

### 6.4 页面上下文差异

不同页面下，Agent 抽屉默认承接不同上下文：

- 在聚合工作台：偏向“理解信息并转成任务”
- 在日程详情页：偏向“修改任务、拆任务、改优先级、重排时间”
- 在订阅配置页：偏向“解释规则、调整提醒策略、查看异常状态”
- 在成长档案页：偏向“结合长期目标调节阶段计划与建议口径”

## 7. 任务理解与多智能体协同闭环

### 7.1 闭环目标

知途要表达的不是“AI 给一个回答”，而是“AI 帮用户完成一次从信息到行动的闭环”。

### 7.2 标准流程

本轮统一定义的前端闭环为：

**任务引用 / 选中 → 任务理解 → 协同决策 → 对话内编排 → 用户确认 → 回写日程 / 提醒 / 执行队列 → 结果反馈**

### 7.3 任务理解（Understand）

触发入口包括两类：

- 用户主动在 Agent 抽屉中提问
- 用户点击或引用主页面中的任务卡 / 信息卡

任务理解结果应以结构化方式呈现，而不是只给一段自然语言。建议包含：

- 事件是什么
- 为什么重要
- 是否存在截止时间
- 是否存在时间冲突或优先级冲突
- 建议进入哪类处理流程

### 7.4 协同决策（Plan）

前端上不强调底层算法，而强调“多 Agent 协同输出一个可行动的结论”。

建议通过 **协同决策面板** 展示：

- 信息研判 Agent 的判断摘要
- 日程规划 Agent 的排期建议
- 策略支持 Agent 的优先级建议
- 汇总后的行动建议卡

### 7.5 对话内编排（Orchestrate）

用户可以在 Agent 对话中直接修改与编排任务，例如：

- 拆分任务
- 修改时间
- 调整优先级
- 并入某条长期目标主线
- 加入日程 / 提醒 / 执行队列

Agent 对这些操作的响应不应只是文本，而应以 **结构化修改预览卡** 呈现。预览卡至少包含：

- 修改前
- 修改后
- 影响范围
- 确认按钮
- 取消按钮

### 7.6 用户确认（Confirm）

所有涉及回写的动作都必须经过用户确认。

当前 demo 中允许被前端表达的动作包括：

- 加入日程
- 生成提醒
- 加入执行队列

本轮 spec 明确采用“前端闭环表达”，因此不承诺真实外部平台自动执行。

### 7.7 结果反馈（Feedback）

所有动作执行后，都必须在界面里留下明确结果，而不是只通过瞬时提示表达。

系统需要能表达以下状态：

- 已加入日程
- 已生成提醒
- 已进入执行队列
- 等待用户确认
- 当前不可自动执行

这些状态应同时在日程详情页和 Agent 抽屉中可被感知。

## 8. 卡片引用入对话与对话反向改任务

### 8.1 任务卡片引用入对话

每张信息卡、任务卡或目标卡都应具备进入 Agent 对话的轻量入口。

推荐提供两种方式：

- **引用到助手**
- **拖拽到 Agent 抽屉输入区**

进入对话后，卡片不应被普通文本替代，而应转化为一个轻量级 **引用块（Quote Block）**。引用块至少保留：

- 标题
- 来源
- 时间 / 截止日
- 当前状态

当卡片被引用后，原页面中的对应卡片应保持轻微高亮，以建立页面与对话之间的视觉映射关系。

### 8.2 对话中直接修改任务

用户在对话中可以直接发出操作型指令，例如：

- 帮我拆成三个子任务
- 改到下周三
- 调成高优先级
- 放到考研复习主线里

系统返回的不是单段文本，而是 **任务修改预览卡**，用于让用户看清本次改动。

### 8.3 修改预览卡规范

修改预览卡应包括：

- 原任务信息
- 新任务信息
- 被新增的子任务或变更字段
- 对日程或提醒的影响
- 确认 / 取消操作

确认后，主页面任务状态同步更新；取消后，不发生落地修改。

### 8.4 反向定位与双向联动

在 Agent 对话中点击某条引用任务时，主页面应自动定位到对应卡片或对应日程项，形成双向联动。

这一能力用于强化“对话不是脱离页面的独立聊天窗口，而是当前页面的操作中枢”这一认知。

## 9. Skill 规则的前端表达

### 9.1 表达目标

《作品报告》第三章中关于 Skill 的能力自描述、强类型约束、输入输出规范、执行限制与异常回执，不在本轮以技术细节方式展开，而是以前端规则表达方式落地。

### 9.2 前端中的呈现方式

建议通过订阅配置页中的三个区域完成表达：

- **Skill 规则区**：展示某类输入会调用哪类能力，产出哪类结果
- **动作限制区**：展示哪些动作只能建议、哪些动作需要确认后回写
- **异常回执区**：展示“等待确认”“不可自动执行”“仅生成建议”等状态

### 9.3 产品意义

这部分的作用不是让用户理解底层实现，而是让评委看到：知途并不是让 Agent 任意生成，而是具备明确的输入边界、处理职责与结果约束。

## 10. 微交互与产品感增强规则

### 10.1 高优先级微交互

以下微交互最值得在本轮写入 spec，并优先体现：

- 卡片拖拽到 Agent 输入区时，输入区高亮吸附
- 引用成功后，输入区生成轻量引用块
- 原页面卡片同步边框高亮
- Agent 返回结构化修改预览卡，而非纯文本回答
- 点击对话中的任务引用，主页面自动滚动定位

### 10.2 状态流转表现

对于“已加入日程”“已生成提醒”“已确认执行”等状态，应使用可见状态块、标签或结果卡表达，而不是只通过短暂消息提示。

### 10.3 统一设计原则

所有交互增强都服务于一个目标：

**让用户感受到知途是在围绕任务进行编排，而不是在做一次次割裂的聊天。**

---

## 11. 本轮落地范围与非范围

### 11.1 本轮明确纳入范围

- 知途产品命名与定位重构
- 4 主页面 + 右侧常驻 Agent 抽屉的信息架构
- 四大区域的产品映射
- 任务理解、协同决策、对话编排、执行确认、结果反馈的前端闭环
- 卡片引用入对话与对话反向改任务
- Skill 规则、动作限制与异常回执的前端表达

### 11.2 本轮暂不纳入范围

- 隐私安全细则的展开设计
- 真实 OpenClaw 外部执行细节
- 真实 RAG 数据结构与长期记忆底层实现
- 自动化任务执行成功率、异常补偿与系统架构设计

---

## 12. 最终结论

知途的新一轮迭代 spec，应从“前端展示 demo 说明书”升级为“对齐《作品报告》第三章的产品落地 spec”。

它的核心变化不是多加几个页面，而是把当前 demo 从“信息展示 + AI 对话”推进成“信息进入、任务理解、协同决策、对话编排、确认回写、结果反馈”的完整前端闭环。

在该逻辑下：

- 聚合工作台负责看全局、看重点、进理解
- 日程详情页负责执行、确认与反馈
- 订阅配置页负责规则、来源与回执
- 成长档案页负责长期目标与上下文外显
- Agent 抽屉负责承接引用、理解任务、编排任务与触发回写

这套结构既贴合当前 project 的已有进度，也能够稳定承接《作品报告》第三章中最需要落地的内容。
